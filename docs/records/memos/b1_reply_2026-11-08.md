## 2. 必修：模擬題池的洩漏

ct9 的 24 個成員（`results/models/ct_cv_m33/val{1..4}_{C,T}-pc-f0-x40-oh_s{0,1,2}.pt`）帶 M33 玩家對比損失，模型被明確訓練成「同一玩家的題目聚在一起」。對官方候選人（不在訓練集）這是優點；對題池這是洩漏來源——候選人只要被模型看過，B1 在題池上的分數就會虛高，步驟 4 的 80% 門檻失效。題池要同時滿足：

- fold v 的玩家只用 `val{v}_*` 六個成員（你們已寫）；
- L1b 頭也避開 fold：`heads3_A` 訓練於 fold 1、2，`heads3_B` 訓練於 fold 3、4。fold 1、2 的玩家在 predict 階段加 `--l1b-names heads3_B`，fold 3、4 的加 `heads3_A`；
- 訓練側的分數表（`results/scores_hd`、`results/l1b/*_hd`、`results/trunk_vec/fold{v}`）每位玩家只涵蓋 20 局，候選人 100 局多數沒有分數，要走下面的測試側流程重新打分。題池按 fold 分成 4 份 CSV 各跑一次（shard 檔綁定題目雜湊，不能混）。

## 3. 流程：官方測試格式 → ct9 測試側三段

格式見 `src/aicup/submission.py`：`question_id, num_games, sgf_1..sgf_20, color_1..color_20`，`1 ≤ num_games ≤ 20`，question_id 要有 `pub_` 或 `priv_` 前綴，執行時以 `--expect-rows N --expect-public N --expect-private 0` 宣告題數。你們的 Public 題目檔本來就是這個格式（`pub_q_0001`…，5／10／15／20 局各 100 題）；候選人 100 局切 5 組×20 局，題號 `pub_c0001_k0`…`k4`。

```
# (1) 逐局打分：18 個 Human SL 檔位 + L1b 頭 + 對手兩道（預設開）
bash scripts/nano4/shards.sh 8 python -I scripts/predict_submission.py --inputs CSV... --out OUT/submission_rank.csv \
    --l1b-heads results/l1b/heads3_A.pt results/l1b/heads3_B.pt --workers 10 --expect-rows N --expect-public N --expect-private 0
python -I scripts/predict_submission.py --merge --nshards 8 --inputs CSV... --out OUT/submission_rank.csv （同樣的 --l1b-heads 與 --expect-*） \
    --fused-model results/models/rank_model_fused_opp_diff_hd_r.json --allow-missing-hd
# (2) 逐手 trunk 向量
bash scripts/nano4/shards.sh 8 python -I scripts/trunk_predict.py extract --inputs CSV... --vec OUT/vec --workers 10 --expect-*
# (3) 10 維機率：官方候選人用 24 個成員；題池第 v 份只放 val{v} 的 6 個，並加 --l1b-names
python -I scripts/trunk_predict.py predict --inputs CSV... --shards OUT/submission_rank.csv --nshards 8 --vec OUT/vec \
    --models <checkpoints> --fallback-submission OUT/submission_rank.csv --allow-missing-hd --out OUT/submission_rank_ct9.csv --expect-*
```

第 (3) 段寫出 `OUT/submission_rank_ct9_proba.csv`：每題一列，`question_id` 加 `p_D … p_6D` 十欄。

ct9 的實跡：1 萬局打分不含對手通道 17 分鐘（8 卡），含對手兩道約兩倍；extract 每 1,250 局 378 秒；predict 800 題 70 秒。外推 4.5 萬局約 2–3 小時 8 卡；題池同量再一份。你們文件估的 1 小時偏低 2–3 倍。

## 4. 步驟 3 的 n 不匹配

題目 n 局的向量比 20 局×5 組平均的向量平坦很多，cosine 會多出和身分無關的雜訊。它對題池與 Public 同樣作用，所以步驟 4 的 80% 關卡仍然公平，只是絕對水準偏低。若關卡通過、要進步驟 5，建議改成候選人側按題目的 n 切組（100 局切成 n 局一組，log 機率平均），讓兩側同樣尖銳。這要重新分組 task（predict 目前按 CSV 題目分組），不改碼就得多算幾倍局；改碼約半天，我們可以做。
