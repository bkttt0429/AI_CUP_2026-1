## 2. 競賽規則

來源：[AIdea 競賽頁面](https://www.aidea-web.tw/topic/8c36af8c-2c70-497f-a862-6fb81a53a403)（「從圍棋棋譜預測玩家棋力等級」，AI CUP 2026 圍棋棋力與風格預測競賽－競賽二）。指導單位為教育部資訊及科技教育司，議題提供單位為國立東華大學智慧科技中心。頁面顯示參賽 213 人／138 組。

### 2.1 任務

給一組「查詢棋譜」，預測下出這些棋譜的玩家屬於哪個棋力等級。等級共 10 種：D、C、B、A、1D–6D，與訓練檔一一對應。

### 2.2 評分

每題（一組查詢棋譜）得分：

| 情況 | 得分 |
| --- | --- |
| 等級完全正確 | 1 |
| 差 ±1 級（非完全正確） | 1/e ≈ 0.368 |
| 其他 | 0 |

最終分數 `S_strength = (1/N) × Σ score_i`，N 為題數。

- 這是**有序**評分：預測 3D 而實際是 4D 還有 0.368 分，所以把等級當有序量（回歸、序數分類或機率期望）通常比純分類更划算。
- Baseline 分數為 **0.4631**。Private 排名前 25% 且超過 Baseline 的隊伍（不超過 30 隊）才需交最終報告。
- 比賽期間只看 Public Testing Dataset 的分數，Private 分數不公布，最終名次以 Private 為準，所以要避免對 Public 過擬合。

## 3. 資料結構

### 3.1 總覽

- 10 個棋力等級，由弱到強：`D, C, B, A, 1D, 2D, 3D, 4D, 5D, 6D`
  - 依官方 Tutorial：D = 10–12k、C = 7–9k、B = 4–6k、A = 1–3k，1D–6D 各一段。**級位類別各跨 3 級、段位類別各跨 1 段**，所以段位之間的相鄰類別比級位之間更難分。
- 每等級一個 CSV，各 100,000 列，共 **1,000,000 列**；每列為「某玩家的一盤棋」
- 全部 19×19 棋盤，總玩家數 8,007 人

### 3.2 欄位

`player_id, game_id, rank, color, sgf_content`

| 欄位 | 格式 | 說明 |
| --- | --- | --- |
| `player_id` | 16 位十六進位字串 | 匿名玩家代號，同一玩家各列一致 |
| `game_id` | `g_0000001` … `g_0100000` | 棋譜編號（見 3.4 的注意事項） |
| `rank` | `D…6D` | 該玩家棋力，等於檔名等級 |
| `color` | `B` / `W` | 該玩家本盤執色 |
| `sgf_content` | 單行 SGF | 只含棋盤大小與落子 |

### 3.3 SGF 格式

```
(;SZ[19];B[pd];W[dp];B[qp];W[...];...;B[io])
```

- 開頭固定 `(;SZ[19]`，之後只有 `;B[xx]` / `;W[xx]` 交替落子，座標為 `a–s`（19 路）
- v1.0 **沒有**讓子、勝負（RE）、貼目（KM）、玩家名、日期等任何其他屬性；v1.1（2026-10-31）每局加了 `HD[n]`（讓子數 0–9；HD≥2 的局讓子石仍沒記錄、B/W 標記相反，見 METHOD_NOTES §2.24），其他不變
- 全部黑先、嚴格交替，沒有虛手（pass）
- 直接用標準 CSV 解析器（如 `pandas.read_csv`）讀取；我掃過全部 100 萬列，沒有出現加引號的欄位

### 3.4 統計（我實際掃描 10 個檔案的結果）

| 等級 | 玩家數 | 手數中位數 | 手數平均 | 手數最小/最大 | 每玩家盤數（最小/中位/最大） |
| --- | ---: | ---: | ---: | --- | --- |
| D | 890 | 235 | 227.8 | 100 / 445 | 5 / 44 / 965 |
| C | 817 | 234 | 227.3 | 100 / 445 | 5 / 45 / 1545 |
| B | 1048 | 234 | 226.6 | 100 / 380 | 1 / 37 / 674 |
| A | 1582 | 230 | 223.9 | 100 / 417 | 1 / 24 / 924 |
| 1D | 433 | 230 | 224.0 | 100 / 382 | 1 / 87 / 1505 |
| 2D | 610 | 227 | 221.6 | 100 / 426 | 6 / 76 / 1467 |
| 3D | 618 | 222 | 218.2 | 100 / 398 | 2 / 65 / 1416 |
| 4D | 640 | 221 | 217.5 | 100 / 396 | 9 / 61 / 1800 |
| 5D | 658 | 221 | 218.5 | 100 / 397 | 3 / 64 / 1275 |
| 6D | 711 | 213 | 213.5 | 100 / 383 | 2 / 63 / 1442 |

重點觀察：

- **棋力越高，平均手數越少**（D 約 228 → 6D 約 214），是微弱但單調的訊號。
- 每盤至少 100 手；沒有空棋譜。
- 每檔黑白各半：**前 50,000 列是黑棋（B）、後 50,000 列是白棋（W）**，檔案是依顏色排序的，不是隨機打亂。訓練時要自行 shuffle。
- **每個玩家只出現在一個等級**（8,007 人中跨等級者為 0），所以 `player_id` 與等級完全對應。若測試集的玩家與訓練集重疊，`player_id` 會是極強的特徵，若測試集是新玩家則不能依賴它。這點要等比賽規則確認。
- 每玩家盤數差異很大（最多 1,800 盤），**按玩家切分驗證集**才不會高估成績。

### 3.5 ⚠️ `game_id` 不是全域唯一鍵

`g_0000001`…`g_0100000` 是**每個檔案內各自的流水號**，同一個 `game_id` 在 10 個檔案各出現一次，但內容是不同的棋譜（例如 `g_0000001` 在 D 和 6D 檔的開局完全不同）。抽樣比對也未發現跨檔重複棋譜。若要合併 10 個檔案，請用 `(rank, game_id)` 當鍵，或自行重新編號。

## 6. 官方 Tutorial 與 Baseline（0.4631）

來源：<https://github.com/AILAB-NDHU/AICup-2026-Tutorial>，已 clone 到 `repo/AICup-2026-Tutorial/`（本機與 lab01 都有；lab01 的 `.venv` 已另裝 `sgfmill`、`webdataset`、`matplotlib`）。

| 項目 | Baseline 做法 | 觀察 |
| --- | --- | --- |
| 輸入 | 一局 → `(500, 19, 19)`：取**最後 250 個盤面**，每個盤面拆黑、白兩個平面；不足 250 手在前面補空盤 | 超過 250 手的棋局（全量 33.7%：D 36.8% 遞減到 6D 29.7%）**開局被截掉**；500 層全盤歷史很浪費，網路得自己學「相鄰盤面相減 = 落子」 |
| 目標玩家 | **沒有用 `color`**，也沒有用 `player_id` | 模型看的是整局棋（兩個人下的），卻用其中一人的等級當標籤；對手等級不同時就是標籤雜訊 |
| 模型 | `GoRankResNet`：20 個 residual block、256 通道，1×1 conv 降到 6 層 → FC 722 → 10 類 | 參數量約 2 千多萬；需 8.6 GB VRAM |
| 訓練 | AdamW lr 1e-3、batch 256、**5 epochs**、CrossEntropy；以 val **accuracy** 挑 checkpoint | 選模型用的是 accuracy，不是比賽的 ±1 加權分 |
| 驗證切分 | 全量 shuffle 後隨機切 100,000 局 | **沒有依 `player_id` 分組**，同一玩家的棋同時在 train 與 val |
| 推論 | 每題各局分別 softmax → **機率平均** → argmax | 可改為對數機率相加、或依 2.2 的期望得分規則決策 |
| 特徵存放 | WebDataset `.tar.gz` 分片，train 1.5 GB + val 163 MB；`__key__` 用 `rank_gameid` 避免跨檔 `game_id` 重複 | 抽特徵是一次性作業，多進程 |
| 官方環境 | RTX 4090 24 GB、Python 3.10、torch 2.6+cu124 | lab01 兩張 96 GB 可以放大模型與 batch |

另一個子題（玩家辨識，Task 1）的 baseline 是 `GoPlayerResNet` + Triplet Loss，用 17 層平面（我方 8 手歷史 + 對方 8 手 + 執色），public 0.2845。它的特徵設計反而比 Task 2 的 baseline 合理（有區分我方／對方、有執色平面）。

### 6.1 已驗證：對手不在資料集中

對全部 100 萬局的 `sgf_content` 去重：**1,000,000 局全部唯一**，沒有任何一局同時以黑方、白方身分出現在兩個等級檔。所以資料集每局只取一位玩家，對手的等級不可知；之前 3.5 節「抽樣比對」的結論在全量上成立。

### 6.2 資料健全性抽樣（lab01，2026-10-15）

- **手數 ≥ 250 的棋局比例**（會被 baseline 截掉開局）：D 36.8%、C 36.2%、B 36.2%、A 34.7%、1D 35.1%、2D 33.5%、3D 31.2%、4D 31.4%、5D 32.9%、6D 29.7%；全量 33.7%。比例隨棋力單調下降，所以「是否被補空盤、補幾張」本身就帶有棋力訊號（= 局長），改輸入表示時要意識到這點。
- **合法性**：每級隨機抽 1,000 局（共 10,000 局）用 `sgfmill` 逐手重播：解析失敗 0、落在已有子的點 0、違反簡單打劫 0、虛手 0。`sgfmill` 的 `play()` 不檢查自殺與 superko，這兩項未驗證。測試集 11/04 發佈後要對 `sgf_1…sgf_20` 重跑同樣檢查，不能假設它和訓練集一樣乾淨。
- 腳本：lab01 `~/AICUP_2026-1/scripts/movecount.awk`、`scripts/check_legal.py`（`.venv/bin/python -I scripts/check_legal.py <每檔抽樣數> data/training/train_*.csv`）。
